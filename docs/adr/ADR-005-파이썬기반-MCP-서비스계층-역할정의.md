# ADR-005: 파이썬 기반 MCP 서버 분리 및 서비스 계층 역할 정의

## 상태
Accepted

## 결정 시점
2026-02-20

## 배경
AI를 활용한 데이터 분석 및 블로그 초안 생성 기능을 구현함에 있어 다음과 같은 기술적 한계와 설계적 고민이 있었음:

- **분석 로직의 부하**: AI를 통한 세션 데이터 분석 및 가공 로직은 자원 소모가 크며, 메인 API 서버(Spring Boot)의 성능과 안정성에 영향을 줄 수 있음.
- **AI 생태계**: MCP(Model Context Protocol) 표준 SDK와 데이터 처리 관련 라이브러리(LangChain, NLP 등)는 자바보다 파이썬 생태계가 업데이트가 빠름.
- **책임 분리의 어려움**: AI 호출(기술적 통신)과 블로그 작성(비즈니스 시나리오)이 하나의 서비스에 섞일 경우, 코드의 가독성이 떨어지고 테스트 코드 작성이 복잡해짐.

## 결정
1. **별도 MCP 서버 구축**: 분석 로직과 DB 직접 접근(분석용)을 담당하는 MCP 서버를 **파이썬(Python)** 프로젝트로 완전히 분리하여 구축함.
2. **AiService의 경량화 (Minimalist Bridge)**: `AiService`는 도메인 지식 없이 오직 AI와의 통신(LlmClient 호출)과 결과 텍스트 추출만을 담당하는 순수 유틸리티로 제한함.
3. **DraftService의 역할 강화 (Orchestrator)**: 블록 데이터 조립(`contentJson` 가공), 프롬프트 설계, 최종 저장 등 **블로그 초안 생성이라는 비즈니스 시나리오의 흐름 제어**를 전담함.
4. **AnalysisService의 역할 전환**: 직접 분석을 수행하는 대신, 분석 프로세스의 시작을 트리거하고 진행 상태(중, 완료, 실패)를 관리하는 **매니저** 역할로 정의함.

## 이유
- **단일 책임 원칙(SRP) 준수**: 기술적인 AI 통신(AiService)과 도메인 로직(DraftService)을 명확히 분리하여 객체지향적인 설계를 유지함.
- **최적의 기술 스택 활용 (Polyglot)**: MCP SDK 지원이 가장 강력한 파이썬을 선택하여 개발 속도를 높이고, AI 엔진과 비즈니스 서버 간의 결합도를 낮춤(Decoupling).
- **시스템 안정성 및 확장성**: 무거운 분석 로직을 별도 서버로 격리하여 메인 서버의 자원을 보호하고, 향후 분석 엔진만 독립적으로 확장하거나 교체하기 쉬운 구조를 지향함.
- **신입 개발자 역량 증명**: 단일 모놀리식 서버를 넘어 다중 서버 아키텍처를 설계하고 연동하는 경험을 통해 기술적 차별성과 아키텍처 설계 능력을 확보함.

## 결과
- **구조적 변화**: Spring Boot 서버는 제어(Control)에 집중하고, Python 서버는 실행(Execution)에 집중하는 명확한 분업 구조가 확립됨.
- **테스트 용이성**: `AiService`를 가볍게 유지함으로써 `DraftService`의 비즈니스 로직을 독립적으로 검증하기 위한 단위 테스트 작성이 용이해짐.
- **유지보수 효율**: AI 모델이 바뀌거나 분석 방식이 변경되어도 각 서비스가 맡은 역할이 분명하여 수정 범위를 최소화할 수 있음.
